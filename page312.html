Animating the Unanimatable

📅 Feb 15, 2016  |  Category: Business  |  Read Source →

This post was originally published in 2016, and has not been kept up to date. All of the code uses React class components, which aren’t recommended to be used today.

The core animation ideas are still worthwhile, but I wouldn’t trust any of the code, and I'd suggest using Framer Motion(opens in new tab) for doing this type of animation.

Between CSS3 transitions, @keyframe animations, and wonderful new technologies like the upcoming Web Animations API(opens in new tab), we've never had more control when it comes to building animations on the web.

There’s still one thing that none of these technologies can handle out of the box, though; animated list reordering.

We have a parent ArticleList component which takes a list of articles as its props. It maps through them, in order, and renders them.

If that list order changes (examples: the user toggles a setting that changes the sorting, an item gets upvoted and changes position, new data comes in from the server…), React reconciles the two states, and updates the DOM, creating new nodes, moving existing nodes, or destroying nodes.

If an item is removed from its original location and re-inserted at a new location 200px down, it has no awareness about what that update means for the element’s on-screen position.

Because the element’s CSS properties haven’t changed, there is no way to use CSS transitions to animate this change.

How can we get the browser to behave as though these elements have moved? The solution to this problem will take us on a ride through low-level DOM operations, React lifecycle methods, and hardware-accelerated CSS practices. There will even be some basic maths!

To solve this problem, there are a few pieces of info we need, and we need them at a very specific moment in time. Let’s forego the complexity in acquiring them, for now, and operate on the assumptions that:

Here’s what our situation might be: We have a list of 3 items, and they were just reversed. We know their original position (left side), and we know where they’re moving to (right side).

A quick aside: It may surprise you to learn that there exists a moment in time where we can tell where an item will be before it has been painted to the screen.

When you think about it, it makes sense; how can the browser paint new pixels to the screen before it knows exactly where to paint them?

Thankfully, this is not a black box; The browser updates in distinct steps, and it is possible to execute logic between calculating the layout and painting to the screen.

But how do we access the calculated layout?

DOM nodes have an incredibly helpful native method, getBoundingClientRect(opens in new tab). It gives us the size and position of the target element relative to the viewport. Here’s what it might give us if we called it on that top blue rectangle, before the new layout is calculated:

getBoundingClientRect is smart enough to work out the new layout position of an element, taking into account its height, margin, and any other variables that will affect where it is in the viewport.

Armed with these two pieces of data, we can work out the change in the element’s position; its delta.

So, we know that the element has moved down 132px. Similarly, we know that the middle item hasn’t moved at all (Δy = 0px), and the last item has moved up by 132px (Δy = -132px).

The problem is, while we know all these facts, the DOM is about to update; In the blink of an eye, those boxes will instantly be in their new position!

This is where the next tool in our arsenal comes in: requestAnimationFrame(opens in new tab).

This is a method on the window object that tells the browser “Hey, before you paint any changes to the screen, can you run this bit of code first?”. It’s a way to quickly make any adjustments needed before the elements are updated.

The thing is, we’ve made it so that we’re in a situation where regular CSS transitions can work again. To animate these elements to their new position, we can add a transition and undo the artificial position changes.

This technique was popularized by Google’s Paul Lewis, and he calls it the FLIP technique(opens in new tab). FLIP is an acronym for First, Last, Inverse, Play.

Our version is a little different, but it’s the same principle.

While learning about this technique and writing my module, I learned quite a bit about DOM rendering. While most of what I learned is out of the scope of this article, there’s one tidbit we should take a quick look at: the difference between painting and compositing, and its effect on selecting hardware-accelerated CSS properties.

Originally, browsers did everything with the CPU. In recent years, some very smart people figured out that certain tasks could be delegated to the GPU for massive gains in performance; specifically, when the “texture” of a static piece of content doesn’t change.

The primary objective was to speed up scrolling; when you scroll down a page, none of the elements are changing, they’re just sliding up. The browser people were kind enough to also allow certain css properties to work the same way.

By using the transform suite of CSS properties — translate, scale, rotate, skew, etc — and opacity, we aren’t changing the texture of an element. And if the texture doesn’t change, it doesn’t have to be re-painted on every frame; it can be composited around by the GPU. This is how to achieve 60+fps animations.

La bintje est dite « de consommation » (on se demande quelle est la finalité des autres patates), avec une chair « farineuse ». Guère engageant. Kornelis Lieuwes de Vries, l'obtenteur (c'est-à-dire le papa) de cette pomme de terre, l'a nommée en hommage à l'une de ses élèves. La Bintje se caractérise également par sa grosse taille et sa rondeur (le sieur de Vries aimait-il les femmes bien en chair ?). Alton Brown's Brined Turkey

📅 Nov 18, 2011  |  Category: Food  |  Read Source →

If you’re wondering how to fit an enormous brine-bathing bird into your fridge this holiday season, stop wondering. Alton Brown’s wet-brined turkey recipe uses an insulated cooler instead, freeing up precious refrigerator space while seasoning the bird throughout.

The brine—a simple mixture of kosher salt, sugar, and vegetable broth—helps the turkey retain moisture as it roasts. Once the bird has had its soak, pat it thoroughly dry and send it into a blazing-hot 500°F oven to get the skin hurtling toward golden and crisp. After 30–40 minutes, you’ll shield the breast with foil, lower the heat to 350°F, and let the turkey finish roasting.

That’s right: No basting. No hovering by the oven. Just a little advance planning and plenty of time to focus on sweet potatoes, apple pie, and the rest of your Thanksgiving feast.

If you'd rather skip the wet brine, try our dry-brined turkey. Short on time? Chris Morocco’s turkey in parts cooks in under two hours.

For a 14–18-lb. turkey, plan on 8–12 hours in the brine—enough time for the salt to work its way into the meat, seasoning it and helping it retain moisture. You may be tempted to leave the turkey soaking for 24 hours, but an extended brine can make it overly salty. Stick to the recommended window.

Yes, as long as you can keep the brine at or below 40°F the entire time. Use a thoroughly cleaned, food-safe insulated cooler and monitor the liquid with a probe thermometer. Add sealed ice packs as needed to maintain a safe temperature. The goal is to keep the turkey just as cold as it would be in the refrigerator.

Can you brine a turkey that’s already been brined?

It’s best not to. Many supermarket turkeys are sold prebrined or injected with a salt solution, sometimes labeled “self-basting,” “enhanced,” or “contains a solution.” Brining one again can make the meat too salty. Check the packaging before you begin and choose an unbrined turkey for this recipe.

How do you keep gravy made from brined turkey from getting too salty?

Brining seasons the turkey, but it can also make the pan drippings quite salty. Taste the gravy before adding any extra seasoning, and use low-sodium or unsalted broth for more control. If the finished gravy is too salty, add a few pats of unsalted butter or thin the gravy with salt-free broth.

Place wrapped one 14–18-lb. Frozen turkey in a 5-gal. cooler with a drain spout. Place cooler in a bathtub and pour in cold water to cover turkey. Let sit, draining and replacing water every 2–3 hours and making sure to keep water temperature below 40°, until turkey is thawed, 8–10 hours.

Remove turkey and clean cooler with soap and pat dry. Pour in 3 cups (1 lb.) Diamond Crystal or 1¾ cups Morton kosher salt, ⅔ cup sugar, and 2 qt. hot tap water. Stir to dissolve salt and sugar. Pour in 4 qt. low-sodium vegetable broth and 8 lb. ice (from 1 gallon water).

Unwrap turkey and remove giblets and any other parts (such as neck) that may be inside cavity; save for gravy if desired. Place turkey, breast side up, in brine. If turkey floats, fill a 1-gallon resealable plastic bag with ice water and place it on top of turkey. Close lid and set cooler in a cool place. Let sit, turning turkey over once if possible, 8–12 hours. Check brining liquid periodically with a probe-style thermometer ; if temperature is above 40°, add a few freezer packs enclosed in resealable plastic bags.

Place a rack in lower third of oven and remove remaining racks; preheat to 500°. Remove turkey from brine and pat dry inside and out with paper towels. Fill turkey cavity with 1 large onion, coarsely chopped, 2 large carrots, scrubbed, coarsely chopped, 2 celery stalks, coarsely chopped, and some thyme, rosemary, and/or sage sprigs; keep packing loose.

Place turkey, breast side up, on a V-shaped rack set inside a large roasting pan. Cut a piece of foil big enough to cover breast and mold over breast. Remove foil, then coat foil with nonstick vegetable oil spray and set aside.

Rub 2 Tbsp. unsalted butter between your hands until liberally coated (you may use disposable food-grade gloves if desired). Rub butter all over turkey, re-buttering your hands and repeating process until you have a nice, even coating.

Slide turkey into oven neck end first and roast until well browned, 30–40 minutes. Remove turkey from oven and place greased foil over breast. Insert probe-style thermometer through foil into thickest part of breast. Reduce oven temperature to 350° and return turkey to oven. Roast until probe inserted into breast registers 161°, and 181° for thigh, 2–2½ hours (do not open oven to baste turkey).

Transfer turkey to carving board and let rest 30 minutes. Reserve drippings for gravy.

Set roasting pan across 2 burners over medium heat. Add 1 cup low-sodium chicken broth and whisk to scrape up pan drippings. Whisk 1 Tbsp. cornstarch and 1 cup cold water in a small bowl to combine. Add cornstarch slurry to pan and cook, whisking, until gravy is glossy and thickened. Taste and season with kosher salt and freshly ground pepper if needed.
